# Logic Link

A deterministic number-matching puzzle. Match equal numbers or pairs that sum to 10 (horizontal, vertical, diagonal, wrap-around) to clear the board. Every level is generated by a constraint-first engine that guarantees solvability and a controlled difficulty curve — no random unfair boards.

Live app: https://puzzle-logic-forge.lovable.app

## Tech stack

- TanStack Start + React 19 (UI)
- Pure TypeScript engine in `src/engine/` (zero React deps, portable)
- Vitest for tests, Vite for build, PWA-installable
- MCP server exposed at `/mcp` (`new_game`, `legal_moves`, `next_move`, `simulate_level`)

## Getting started

```bash
bun install       # or: npm install
bun run dev       # local dev server on http://localhost:8080
bun run build     # production build
bun run test      # engine + simulator tests
```

Open `/play` to play. Use the on-screen toggle to reveal the Debug Overlay (seed, solvability, AI-suggested move, legal-match graph).

## Running the solver

The solver is a pure function on the engine's public API — no UI needed.

```ts
import { createGame, isSolvable, findAllLegalMoves, applyMove } from "@/engine";

const game = createGame(3);                     // Level 3, deterministic seed
const solvable = isSolvable(game.board);        // DFS solver, bounded search
const moves = findAllLegalMoves(game.board);    // all H/V/D/wrap matches
const next = applyMove(game, moves[0].from, moves[0].to);
```

To batch-verify probabilistic fairness across many boards, run the simulation harness:

```bash
bun run scripts/simulate.ts           # 1000 trials per level, all 10 levels
bun run scripts/simulate.ts --level 5 # single level
bun run scripts/simulate.ts --trials 5000
```

It reports per-level completion rate, median/p95 solve time (heuristic AI), and Add Row usage. CI gate lives in `src/engine/__tests__/simulator.test.ts`.

## Add Row flow

Each level starts with 3 rows and a budget of 6 Add Rows. Add Row never appends random numbers — it runs this pipeline:

```text
Board analysis → Need detection → Smart row generation → Validation → Insert
```

1. **Analyze** — find stranded values (rows with 1 remaining number), dead cells, and legal-move count.
2. **Generate** — build a candidate row that prioritizes clearing stragglers, then completing buried pairs, then controlled decoys (weights come from `LevelConfig`).
3. **Validate** — reject candidates that reduce legal moves below the acceptance threshold.
4. **Rescue** — if two consecutive Add Rows fail to unlock a match, force a guaranteed-match row (e.g. `7` next to `3`) and reset the counter.

From code:

```ts
import { addRow, createGame } from "@/engine";

let game = createGame(2);
game = addRow(game);           // consumes 1 of 6; returns new immutable state
console.log(game.addRowsRemaining, game.rescueCounter);
```

Invalid inputs (out-of-budget, game over, empty board) return the same `GameState` reference — the engine never throws for gameplay errors.

## Difficulty configuration

All difficulty knobs live in `src/engine/config/levels.ts` as a `Record<number, LevelConfig>`. No gameplay constants are scattered in code — tune a level by editing its config entry.

Key fields per level:

| Field | Purpose |
| --- | --- |
| `difficultyScore` | Human-readable rank driving the sawtooth curve |
| `matchDensity` | Fraction of cells that participate in immediate pairs |
| `directPairWeight` / `buriedPairWeight` | Visible vs. scan-required matches |
| `clusteringWeight` | How tightly matched pairs cluster on the board |
| `decoyWeight` | Non-matching filler that increases scanning effort |
| `helperStrength` / `cleanupPriority` | Smart Add Row bias toward assisting the player |
| `expectedAddRowDistribution` | Target Add Row usage histogram (index = # of Add Rows) |
| `targetCompletionTime` | Playtest target in seconds |
| `completionProbability` | Target completion rate (~90–95%) |
| `fairnessThreshold` | Min. fraction of legal move orderings that must still solve |
| `initialCellCount` | Filled cells at start; must be even (solvability invariant) |
| `addRowBudget` | Add Rows granted per level (default 6) |
| `seedStrategy` | `"ruleBasedVaried"` = variation inside a pre-validated envelope |

Sawtooth curve is intentional: L1→L5 rises, L6 dips to ≈L3 ("breath of fresh air"), L7→L10 rises past the L5 peak. To add Level 11+, append an entry to `LEVEL_CONFIGS` and it becomes selectable in the UI and the simulator automatically.

Full algorithm writeup: [`docs/ALGORITHM.md`](./docs/ALGORITHM.md).

## Project structure

```text
src/
  engine/          Pure TS engine (generator, solver, addRow, rescue, simulator)
    config/        Level configs — edit here to tune difficulty
    __tests__/    Vitest suites (invariants, generator, solver, simulator)
  hooks/useGame.ts React binding over the engine
  components/      Board, Cell, GameHeader, GameControls, DebugOverlay
  routes/          TanStack routes: / (landing), /play (game), /mcp (agent)
  lib/mcp/         MCP tool implementations
scripts/simulate.ts CLI harness for probabilistic validation
docs/ALGORITHM.md   Engine internals + sawtooth definition
```
